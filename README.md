# ERLI Monitor

Веб-приложение для мониторинга заказов и аналитики рекламы магазина на маркетплейсе [erli.pl](https://erli.pl).

## Возможности

- **Заказы** — локальная база заказов (SQLite) с фильтрами, поиском и сортировкой; статусы оплаты и отправки (по-польски, как в панели магазина)
- **Поллинг inbox** — фоновый опрос событий ERLI каждые 60 секунд (новые заказы, смены статусов)
- **Синхронизация** — каждые 10 минут одним запросом забираются все заказы, изменённые с прошлого раза; ловит и то, что пропустил inbox
- **Загрузка истории** — кнопка «Загрузить с даты» забирает все заказы магазина начиная с выбранного дня, включая нерекламные
- **Аналитика рекламы** — загрузка xlsx-выгрузки статистики кампаний: показы, затраты, фактический ROAS (без отмен и неоплаченных), продано теплиц, цена одной продажи
- **Обслуживание** — ручное добавление заказа по ID, удаление по одному или до даты

## Установка (локально)

1. Python 3.12+
2. `pip install -r requirements.txt`
3. Скопировать `config.example.json` → `config.json` и вписать API-ключ ERLI (раздел «Интеграции» в панели магазина)
4. Запуск: `start.bat` или `python app.py` → откроется http://127.0.0.1:5000

Локально данные хранятся в SQLite (`erli.db`), пароль не требуется.

## Деплой на Render.com

Проект готов к деплою через `render.yaml` (gunicorn, 1 worker). Переменные окружения:

| Переменная | Назначение |
|---|---|
| `ERLI_API_KEY` | API-ключ ERLI (вместо config.json) |
| `APP_PASSWORD` | Пароль входа — обязательно на публичном сервере |
| `DATABASE_URL` | Строка подключения Postgres (например, Neon) — без неё данные не переживут редеплой |
| `SECRET_KEY` | Ключ сессий Flask (Render генерирует сам) |

xlsx-выгрузки хранятся в базе данных, поэтому переживают перезапуски.

## Структура

| Файл | Назначение |
|---|---|
| `app.py` | Flask-приложение, маршруты |
| `erli_api.py` | Клиент REST API ERLI |
| `db.py` | Слой SQLite (`erli.db`) |
| `poller.py` | Фоновый опрос inbox + автообновление статусов |
| `report.py` | Отчёт по рекламе (join xlsx + заказы) |
| `templates/` | HTML-страницы (Jinja2) |
| `uploads/` | Загруженные xlsx-выгрузки (не в git) |

## Заметки по API ERLI

- `POST /orders/_search` с **пустым телом** отдаёт заказы с самого первого (2021 год) — когда-то это приняли за «застрявший курсор». Нужен явный фильтр и сортировка:
  ```json
  {"filter": {"field": "created", "operator": ">=", "value": "2026-08-01T00:00:00Z"},
   "pagination": {"sortField": "created", "order": "DESC", "limit": 200}}
  ```
  `limit` — максимум 200. Следующая страница: поле `cursor` последнего заказа передаётся в `pagination.after`. Фильтровать можно и по `updated`.
- В xlsx-выгрузке рекламы есть только заказы, атрибутированные рекламе. Нерекламные приходят только через синхронизацию или inbox.
